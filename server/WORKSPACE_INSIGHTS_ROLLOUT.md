# Workspace Insights rollout

`315_workspace_insights.js` adds scoped usage and sales projections and leaves Insights and the missing-price guard disabled. It does not rewrite historical wallet transactions. Deploy the migration with the other pending migrations in numerical order.

1. As a superadmin, call `GET /api/admin/insights/readiness`. The response lists active and recently used models without verified rates, and compares the business-scoped ledger with its process breakdown. Missing historical credit conversion rates are reported separately; they do not block activation because the dashboard marks their INR coverage incomplete.
2. For each unpriced model, confirm an exact provider/model rate from a trusted rate card or invoice, then call `POST /api/admin/insights/pricing-overrides`. Example text override: `{"kind":"llm","provider":"openrouter","model":"provider/model-id","inputUsdPerMillion":0.5,"outputUsdPerMillion":1.5,"sourceReference":"provider rate card, 2026-09-29"}`. For `image` or `video`, supply `unitUsd` (per image or per video second) and optional `resolutionTiers`. For `embedding`, supply `inputUsdPerMillion`. These writes use the existing API pricing audit history.
3. Re-run readiness until `unpriced` is empty and `reconciliation.differenceCredits` is `0.00`. Check sampled `wallet_transactions` and `ai_usage_events` for linked attempt IDs and compare scoped totals. For payment outcomes, inspect the `source_key`, `payment_id`, `evidence`, and `verified` fields of `sales_outcome_events`.
4. Call `POST /api/admin/insights/activate`. Activation reruns the same checks and enables the page and pricing guard together. Missing prices then fail before a supported AI provider request. The page is at `/dashboard/insights`; `Refresh` bypasses its 60-second scoped cache.

The dashboard reads the wallet ledger for charged credits and recorded INR conversion rates. Usage events describe activity, including unbilled failures. Historical charges with no reliable conversion snapshot remain in credits and the unattributed breakdown; their INR value is shown as incomplete. Periods crossing the instrumentation start are marked partial for retry-level usage and verified payment evidence; older payments are not inferred from a booking's paid status. Demo mode is an in-memory fixture and does not write wallet or usage data.
